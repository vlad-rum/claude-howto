# CLAUDE.md

Репозиторий туториала. Результат — Markdown в нумерованных модулях `01-`–`10-`, а не приложение. Скрипты в `scripts/` нужны только чтобы проверять документацию и собирать EPUB.

См. также `.claude/CLAUDE.md` — стек и команды, и `STYLE_GUIDE.md` — структура урока.

## Критические команды

```bash
# Контроль качества (также запускается при коммите через хуки pre-commit)
pre-commit run --all-files

# Тесты
pytest scripts/tests/ -v

# Сборка EPUB (рисует Mermaid через Pele — нужен Node.js >= 20; закреплённый пакет скачивается один раз, дальше работает офлайн)
uv run scripts/build_epub.py

# Инструменты Python
ruff check scripts/ && ruff format scripts/
mypy scripts/ --ignore-missing-imports
bandit -c scripts/pyproject.toml -r scripts/ --exclude scripts/tests/
```

Pre-commit запускает 5 проверок документации при изменениях `.md`: markdown-lint, cross-references, mermaid-syntax, link-check, markdown-rendering. Все должны пройти. Сборка EPUB — **не** хук pre-commit: она идёт только в CI (задание `build-epub` в `.github/workflows/test.yml`), потому что это медленная сборка всей книги; хук mermaid-syntax уже рисует каждую диаграмму тем же пакетом Pele.

## Карта архитектуры

- `01-` … `10-` — модули туториала. **Числовой префикс = порядок обучения**, не алфавит. Не перестраивайте.
- Каждый модуль: `README.md` и шаблоны, которые можно скопировать (`.md`, `.json`, `.sh`).
- `scripts/` — утилиты (сборщик EPUB, проверки ссылок, Mermaid и перекрёстных ссылок). Это не продукт.
- `02-memory/*.md` — шаблоны CLAUDE.md, которые пользователи копируют в свои проекты. Не путайте с этим файлом.
- `openspec/` — предложения изменений на основе спецификаций.

## Жёсткие правила

- **Не делайте коммит и push без явного запроса пользователя.**
- **Не добавляйте `Co-Authored-By: Claude` ни в одно сообщение коммита.**
- Всегда активируйте `.venv` перед запуском скриптов Python (проверьте `venv/`, `.venv/`, `env/`).
- Внутренние ссылки — **относительные пути** (например, `01-slash-commands/README.md`); якоря имеют вид `#heading-name`.
- У блоков кода **обязательно** указан язык (`bash`, `python`, `json`, …) — иначе проверка перекрёстных ссылок не пройдёт.
- Внешние URL должны открываться и быть устойчивыми. Без эфемерных ссылок.
- Диаграммы Mermaid должны рисоваться через Pele. Хуки mermaid в pre-commit берут Node.js 22 из pre-commit и работают в строгом режиме, поэтому падают, а не пропускают проверку; первому запуску нужна сеть, чтобы скачать Node.js и закреплённый пакет Pele (офлайн: `SKIP=mermaid,vietnamese-mermaid,japanese-mermaid`). При ручном запуске `scripts/check_mermaid.py` только предупреждает, если нет Node.js >= 20, и падает с `--strict` или в CI. Сломанная сборка EPUB обычно означает неверный Mermaid, отсутствие Node.js >= 20 или неудачную загрузку пакета.
- Формат коммита: `type(scope): subject`, где `scope` совпадает с папкой модуля (например, `feat(slash-commands):`, `docs(memory):`, `fix(README):`).
- Не меняйте нумерацию `01-`–`10-`. Этот порядок — учебная программа.

## Предпочтения по рабочему процессу

- При правке уроков следуйте `STYLE_GUIDE.md`: структура, имена, диаграммы.
- Маленькие правки → минимальный diff. Не переписывайте раздел, чтобы исправить опечатку.
- Когда добавляете страницу модуля: сначала README и шаблоны, затем обновите указатель в корневом `README.md` и `LEARNING-ROADMAP.md`, если меняются порядок или сроки.
- Туториал важнее библиотеки: ясные объяснения и примеры, которые можно скопировать, важнее переиспользуемых абстракций.
- Если проверка качества не прошла, исправьте причину. Не обходите её через `--no-verify`.

## Экономия токенов
- Никогда не перечитывайте файлы, которые только что написали или изменили. Вы знаете их содержимое.
- Не запускайте команды повторно «для проверки», если исход был несомненен.
- Не возвращайте большие блоки кода или содержимое файлов, если об этом не попросили.
- Объединяйте связанные правки в одну операцию. Не делайте 5 правок, если хватает одной.
- Пропускайте подтверждения вроде «Продолжаю...». Просто делайте.
- Если задаче хватает 1 вызова инструмента, не делайте 3. Спланируйте, прежде чем действовать.
- Не подводите итог сделанному, кроме случаев, когда результат неоднозначен или нужен дополнительный ввод.
