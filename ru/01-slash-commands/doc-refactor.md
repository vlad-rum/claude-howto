# Рефакторинг документации

Перестройте структуру документации проекта с учётом его типа:

1. **Проанализируйте проект**: определите тип (библиотека/API/веб-приложение/CLI/микросервисы), архитектуру и пользовательские персоны
2. **Соберите документацию**: перенесите техническую документацию в `docs/` с корректными перекрёстными ссылками
3. **Корневой README.md**: сделайте его точкой входа с обзором, быстрым стартом, сводкой модулей и компонентов, лицензией и контактами
4. **Документация компонентов**: добавьте README на уровне модуля, пакета или сервиса с инструкциями по настройке и тестированию
5. **Организуйте `docs/`** по подходящим категориям:
   - Архитектура, справочник API, база данных, дизайн, устранение неполадок, деплой, участие в разработке (адаптируйте под нужды проекта)
6. **Создайте руководства** (выберите подходящие):
   - Руководство пользователя: документация для конечного пользователя приложений
   - Документация API: эндпоинты, аутентификация, примеры для API
   - Руководство разработчика: настройка, тестирование, рабочий процесс вклада
   - Руководство по деплою: деплой в продакшен для сервисов и приложений
7. **Используйте Mermaid** для всех диаграмм (архитектура, потоки, схемы)

Держите документацию краткой, удобной для просмотра и привязанной к типу проекта.
