## Фаза 1 — Инфраструктура и слабые модули (апрель 2026)

**Целевая веха: M1**

### Столп 4: онбординг новичков

- [ ] **T-001** — Написать `scripts/quickstart.sh`
  - Обнаруживает каталог `~/.claude/` (создаёт с подтверждением пользователя, если его нет)
  - Копирует первую слэш-команду + CLAUDE.md + навык в настройку пользователя
  - Дописывает в CLAUDE.md строку обнаружения агентов со ссылкой на AGENT-INDEX.md
  - Идемпотентный: пропускает существующие файлы с предупреждением, никогда не перезаписывает
  - По завершении печатает следующие шаги

- [ ] **T-002** — Создать `QUICKSTART.md` (наглядное руководство «Первые 15 минут»)
  - Аннотированные шаги в терминале как блоки кода (по возможности без PNG-скриншотов; лучше ASCII или Mermaid)
  - Задокументировать, какие команды дают каждую картинку, чтобы их можно было снять заново

- [ ] **T-003** — Добавить значки сложности во все 10 README модулей
  - Формат: `> 🟢 **Начинающий** | ⏱ 30 минут` вверху README каждого модуля
  - Под значком добавить превью-список «Что вы соберёте»

### Столп 7: живая учебная программа

- [ ] **T-004** — Создать `WHATS-NEW.md`
  - Формат: `## CC vX.X — ДАТА` с маркерами по каждому изменению функции
  - Добавить хотя бы одну запись для текущей версии CC

- [ ] **T-005** — Добавить значки версии во все 10 README модулей
  - Формат: `> ✅ Проверено на Claude Code **vX.X.X** · Последняя проверка: YYYY-MM-DD`
  - Добавить `cc_version_verified` во frontmatter каждого модуля

- [ ] **T-006** — Создать `.github/workflows/staleness-check.yml`
  - Расписание: каждый понедельник в 09:00 UTC
  - Читает дату `last_verified` каждого модуля из frontmatter (через `yq` или скрипт Python в 10 строк)
  - Создаёт GitHub Issue для любого модуля, не проверенного 30+ дней
  - Пропускает, если открытый issue с тем же заголовком уже есть

### Столп 6: качество содержания (CLAUDE.md)

- [ ] **T-007** — Создать корневой `CLAUDE.md` проекта
  - Показывает удачные практики как собственная конфигурация проекта
  - Документирует соглашения об участии, структуру модулей и рабочий процесс сопровождения

### Столп 2: индекс для ИИ-агентов (генератор)

- [ ] **T-008** — Написать `scripts/build-agent-index.py`
  - Читает README всех 10 модулей
  - Извлекает: заголовки (→ темы), блоки кода (→ примеры с метками языка), таблицы (→ справочные данные)
  - Выдаёт `agent-manifest.json` со схемой из плана CEO
  - Выдаёт `AGENT-INDEX.md` (сводка для человека)
  - Проверяет, что ссылки указывают на реальные файлы

### Модуль 08-checkpoints: полный глубокий проход (311 → 800+ строк)

- [ ] **T-009** — Переписать вступление модуля на сценарии из практики
  - Пример: «Рефакторинг только что сломал 3 вещи. Вот как контрольные точки вас спасают…»

- [ ] **T-010** — Добавить дерево решений по стратегии контрольных точек (блок-схема Mermaid)
  - «Я хочу сделать X» → идти по стрелкам → попасть на паттерн контрольной точки

- [ ] **T-011** — Добавить 3 шаблона рабочих процессов
  - Рабочий процесс безопасного рефакторинга
  - A/B-тестирование с контрольными точками
  - Рабочий процесс аварийного восстановления

- [ ] **T-012** — Добавить раздел об интеграции с режимом планирования

- [ ] **T-013** — Добавить диаграмму Mermaid жизненного цикла контрольной точки

- [ ] **T-014** — Добавить 2+ блока «Попробуйте сейчас» с проверяемыми командами
  - В каждом: предложение с контекстом, команда для запуска, описание ожидаемого вывода

- [ ] **T-015** — Добавить раздел «Паттерны и рецепты» с 2+ именованными паттернами
  - В каждом паттерне: задача, код решения, когда использовать, когда НЕ использовать

### Модуль 06-hooks: полный глубокий проход

- [ ] **T-016** — Переписать вступление модуля на сценарии из практики
  - Пример: «CI поймал ошибку линтинга через 20 минут. Хуки ловят её за 2 секунды…»

- [ ] **T-017** — Добавить дерево решений по хукам (блок-схема Mermaid)
  - «Я хочу запускать X, когда происходит Y» → идти по стрелкам → попасть на тип хука

- [ ] **T-018** — Добавить 5 полных примеров хуков с целыми скриптами (~80 строк каждый)
  1. Автоформатирование при записи (prettier/black)
  2. Сканирование безопасности при коммите (trufflehog/bandit)
  3. Запуск тестов при изменении файла
  4. Уведомление в конце сессии
  5. Проверка промпта (блокировка опасных паттернов)

- [ ] **T-019** — Добавить 2+ блока «Попробуйте сейчас» с проверяемыми командами

- [ ] **T-020** — Добавить раздел «Паттерны и рецепты» с 2+ именованными паттернами

**Контрольная точка M1: инфраструктура работает, 2 самых слабых модуля полностью обновлены**
