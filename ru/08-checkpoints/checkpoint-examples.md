# Примеры контрольных точек

Практические примеры, как эффективно пользоваться контрольными точками в Claude Code.

Примечание: контрольные точки создаются автоматически с каждым промптом пользователя. Сохранять их вручную не нужно. Чтобы перемотать, нажмите `Esc` дважды (`Esc+Esc`) или выполните `/rewind`, чтобы открыть браузер контрольных точек.

## Пример 1: миграция базы данных

### Сценарий
Нужно перейти с MySQL на PostgreSQL, но хочется сравнить прямую миграцию и постепенный подход с двойной записью.

### Рабочий процесс

```
Пользователь: Давайте сделаем прямую миграцию с MySQL на PostgreSQL
      [Контрольная точка A создана автоматически]

Claude: Я выполню прямую миграцию...
[Меняет драйвер базы данных, обновляет запросы, правит схему]

Пользователь: Запустите тесты
      [Контрольная точка B создана автоматически]

Claude: Запускаю тесты...
❌ 15 тестов падают — проблемы с пулом соединений

Пользователь: У этого подхода есть проблемы. Давайте попробуем шаблон двойной записи.
[Пользователь нажимает Esc+Esc, выбирает контрольную точку A, выбирает «Восстановить код и разговор»]

Пользователь: Теперь реализуйте шаблон двойной записи, при котором мы пишем в обе базы

Claude: Я реализую миграцию с двойной записью...
[Реализует слой двойной записи и стратегию постепенной миграции]

Пользователь: Запустите тесты

Claude: Запускаю тесты...
✅ Все тесты проходят

Пользователь: Подход с двойной записью явно безопаснее. Давайте закоммитим это.
```

## Пример 4: сессия отладки

### Сценарий
Поиск коварной ошибки с несколькими гипотезами.

### Рабочий процесс

```
Пользователь: В приложении утечка памяти
      [Контрольная точка «До отладки» создана автоматически]

[Анализирует код]

Пользователь: Думаю, дело в обработчиках событий. Давайте их исправим.

Claude: [Исправляет очистку обработчиков событий]

Claude: Память всё ещё течёт — дело было не в обработчиках событий

Пользователь: Вернусь и проверю другую гипотезу.
[Пользователь нажимает Esc+Esc, выбирает контрольную точку «До отладки», выбирает «Восстановить код и разговор»]

Пользователь: Может, дело в соединениях с базой?

Claude: [Вносит исправления в пул соединений]

Claude: Всё ещё течёт — и не в соединениях

Пользователь: Давайте поищем циклические ссылки

Claude: [Находит и исправляет циклические ссылки в кэше]

Пользователь: Запустите профилировщик памяти
```

## Пример 8: суммирование из контрольной точки

### Сценарий
После долгой сессии отладки хочется сжать разговор, сохранив контекст.

### Рабочий процесс

```
Пользователь: [После 20+ сообщений отладки и исследования]

[Пользователь нажимает Esc+Esc, выбирает раннюю контрольную точку, выбирает «Суммировать отсюда»]
[При желании даёт инструкцию: «Сосредоточьтесь на том, что мы пробовали и что сработало»]

Claude: [Формирует сводку разговора с этой точки вперёд]
[Исходные сообщения сохраняются в стенограмме]
[Сводка заменяет видимый разговор и уменьшает расход контекстного окна]

Пользователь: Теперь продолжим с подходом, который сработал.
```

## Главные выводы

1. **Контрольные точки автоматические**: каждый промпт пользователя создаёт контрольную точку -- сохранять вручную не нужно
2. **Используйте Esc+Esc или /rewind**: это два способа открыть браузер контрольных точек
3. **Выберите нужный вариант восстановления**: код, разговор, оба или суммирование — в зависимости от задачи
4. **Не бойтесь экспериментов**: контрольные точки делают безопасными даже радикальные изменения
5. **Сочетайте с git**: контрольные точки — для исследования, git — для законченной работы
6. **Суммируйте длинные сессии**: «Суммировать отсюда» держит разговоры управляемыми
