# Контрольные точки и перемотка

Контрольные точки позволяют сохранить состояние разговора и перемотать к предыдущим точкам сессии Claude Code. Это незаменимо, когда вы исследуете разные подходы, восстанавливаетесь после ошибок или сравниваете альтернативные решения.

## Обзор

Контрольные точки позволяют сохранить состояние разговора и перемотать к предыдущим точкам, чтобы безопасно экспериментировать и исследовать несколько подходов. Это снимки состояния разговора, включая:
- Все сообщения, которыми вы обменялись
- Изменения, внесённые в файлы
- Историю использования инструментов
- Контекст сессии

Контрольные точки незаменимы, когда вы исследуете разные подходы, восстанавливаетесь после ошибок или сравниваете альтернативные решения.

## Ключевые понятия

| Понятие | Описание |
|---------|----------|
| **Контрольная точка** | Снимок состояния разговора, включая сообщения, файлы и контекст |
| **Перемотка** | Возврат к предыдущей контрольной точке с отбрасыванием последующих изменений |
| **Точка ветвления** | Контрольная точка, от которой исследуются несколько подходов |

## Доступ к контрольным точкам

К контрольным точкам можно обращаться и управлять ими двумя основными способами:

### Сочетание клавиш
Нажмите `Esc` дважды (`Esc` + `Esc`), чтобы открыть интерфейс контрольных точек и просмотреть сохранённые.

### Слэш-команда
Команда `/rewind` (псевдонимы: `/checkpoint`, `/undo`) даёт быстрый доступ:

```bash
# Открыть интерфейс перемотки
/rewind

# Или используйте псевдоним
/checkpoint
```

## Варианты перемотки

При перемотке появляется меню из шести вариантов:

1. **Восстановить код и разговор** -- вернуть и файлы, и сообщения к этой контрольной точке
2. **Восстановить разговор** -- перемотать только сообщения, текущий код оставить как есть
3. **Восстановить код** -- откатить только изменения файлов, полную историю разговора сохранить
4. **Суммировать отсюда** -- сжать разговор с этой точки вперёд в сводку, которую сформирует ИИ, и освободить место в контекстном окне. Сообщения до выбранной точки остаются нетронутыми. Файлы на диске не меняются. Исходные сообщения сохраняются в стенограмме сессии. При желании можно дать инструкции, чтобы сводка сосредоточилась на конкретных темах.
5. **Суммировать досюда** -- зеркальный вариант назад: сжать всё *до* выбранной точки в сводку, которую сформирует ИИ, а сообщения с этой точки вперёд оставить нетронутыми. Вместе с «Суммировать отсюда» это даёт двунаправленное точечное сжатие контекстного окна. Файлы на диске не меняются, исходные сообщения сохраняются в стенограмме сессии.
6. **Не надо** -- отменить и вернуться к текущему состоянию

> **Примечание**: после восстановления разговора или выбора **Суммировать отсюда** исходный промпт выбранного сообщения возвращается в поле ввода, чтобы вы могли отправить его снова или отредактировать. Выбор **Суммировать досюда** оставляет вас в конце разговора с пустым полем ввода.

> **`/clear` больше не жёсткая граница (v2.1.191+)**: `/rewind` может возобновить работу с контрольной точки, снятой *до* того, как вы выполнили `/clear`. Очистка разговора больше не выбрасывает предшествующее состояние навсегда — можно перемотать назад через очистку, если снова нужен тот код или контекст.

## Автоматические контрольные точки

Claude Code создаёт контрольные точки за вас автоматически:

- **Каждый промпт пользователя** — новая контрольная точка создаётся с каждым вводом пользователя
- **Сохраняются** — контрольные точки хранятся вместе с разговором, поэтому `/rewind` работает и после возобновления сессии
- **Очищаются сами** — контрольные точки автоматически удаляются через 30 дней

Это значит, что перемотать можно к любой предыдущей точке разговора: и к нескольким минутам назад, и к прошлым дням.

## Сценарии использования

| Сценарий | Рабочий процесс |
|----------|-----------------|
| **Исследование подходов** | Сохранить → Попробовать A → Сохранить → Перемотать → Попробовать B → Сравнить |
| **Безопасный рефакторинг** | Сохранить → Рефакторинг → Тест → Если неудача: перемотать |
| **A/B-тестирование** | Сохранить → Дизайн A → Сохранить → Перемотать → Дизайн B → Сравнить |
| **Восстановление после ошибки** | Заметить проблему → Перемотать к последнему хорошему состоянию |

## Использование контрольных точек

### Просмотр и перемотка

Нажмите `Esc` дважды или выполните `/rewind`, чтобы открыть браузер контрольных точек. Вы увидите список всех доступных контрольных точек с метками времени. Выберите любую, чтобы перемотать к этому состоянию.

### Подробности контрольной точки

Каждая контрольная точка показывает:
- Время создания
- Какие файлы были изменены
- Число сообщений в разговоре
- Какие инструменты использовались

## Практические примеры

### Пример 1: исследование разных подходов

```
Пользователь: Давайте добавим слой кэширования к API

Claude: Я добавлю кэширование Redis к вашим эндпоинтам API...
[Вносит изменения в контрольной точке A]

Пользователь: Вообще-то давайте попробуем кэширование в памяти

Claude: Я перемотаю, чтобы исследовать другой подход...
[Пользователь нажимает Esc+Esc и перематывает к контрольной точке A]
[Реализует кэширование в памяти в контрольной точке B]

Пользователь: Теперь я могу сравнить оба подхода
```

### Пример 2: восстановление после ошибок

```
Пользователь: Отрефакторьте модуль аутентификации на JWT

Claude: Я отрефакторю модуль аутентификации...
[Вносит обширные изменения]

Пользователь: Постойте, это сломало интеграцию OAuth. Давайте вернёмся.

Claude: Я помогу перемотать к состоянию до рефакторинга...
[Пользователь нажимает Esc+Esc и выбирает контрольную точку до рефакторинга]

Пользователь: В этот раз давайте попробуем более осторожный подход
```

### Пример 3: безопасный эксперимент

```
Пользователь: Давайте попробуем переписать это в функциональном стиле
[Создаётся контрольная точка перед экспериментом]

Claude: [Вносит экспериментальные изменения]

Пользователь: Тесты падают. Давайте перемотаем.
[Пользователь нажимает Esc+Esc и перематывает к контрольной точке]

Claude: Я перемотал изменения. Давайте попробуем другой подход.
```

### Пример 4: ветвление подходов

```
Пользователь: Хочу сравнить две схемы базы данных
[Замечает контрольную точку — назовём её «Старт»]

Claude: Я создам первую схему...
[Реализует схему A]

Пользователь: Теперь вернусь и попробую второй подход
[Пользователь нажимает Esc+Esc и перематывает к «Старт»]

Claude: Теперь я реализую схему B...
[Реализует схему B]

Пользователь: Отлично! Теперь у меня есть обе схемы, и можно выбрать
```

## Хранение контрольных точек

Claude Code управляет контрольными точками автоматически:

- Контрольные точки создаются автоматически с каждым промптом пользователя
- Старые контрольные точки хранятся до 30 дней
- Контрольные точки очищаются автоматически, чтобы хранилище не росло без предела

## Шаблоны рабочих процессов

### Стратегия ветвления для исследования

Когда исследуете несколько подходов:

```
1. Начните с исходной реализации → контрольная точка A
2. Попробуйте подход 1 → контрольная точка B
3. Перемотайте к контрольной точке A
4. Попробуйте подход 2 → контрольная точка C
5. Сравните результаты B и C
6. Выберите лучший подход и продолжайте
```

### Шаблон безопасного рефакторинга

Когда вносите существенные изменения:

```
1. Текущее состояние → контрольная точка (авто)
2. Начните рефакторинг
3. Запустите тесты
4. Если тесты проходят → продолжайте работу
5. Если тесты падают → перемотайте и попробуйте другой подход
```

## Лучшие практики

Поскольку контрольные точки создаются автоматически, можно сосредоточиться на работе и не думать о ручном сохранении состояния. И всё же держите в уме такие практики:

### Как пользоваться контрольными точками эффективно

✅ **Делайте:**
- Просматривайте доступные контрольные точки перед перемоткой
- Перематывайте, когда хотите исследовать другие направления
- Сохраняйте контрольные точки, чтобы сравнивать разные подходы
- Понимайте, что делает каждый вариант перемотки (восстановить код и разговор, восстановить разговор, восстановить код или суммировать)

❌ **Не делайте:**
- Полагайтесь на одни только контрольные точки для сохранности кода
- Ожидайте, что контрольные точки отследят внешние изменения файловой системы
- Используйте контрольные точки вместо git-коммитов

## Конфигурация

Контрольные точки — встроенное поведение Claude Code по умолчанию, и включать их настройкой не нужно. Каждый промпт пользователя автоматически создаёт контрольную точку.

Две настройки управляют поведением контрольных точек — снимаются ли снимки вообще и как долго они хранятся:

```json
{
  "fileCheckpointingEnabled": true,
  "cleanupPeriodDays": 30
}
```

| Настройка | По умолчанию | Эффект |
|-----------|--------------|--------|
| `fileCheckpointingEnabled` | `true` | Снимать снимок файлов перед каждой правкой, чтобы `/rewind` мог их восстановить. Требует v2.1.119+. В `/config` отображается как **Rewind code (checkpoints)**. Эквивалент в окружении: `CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING` |
| `cleanupPeriodDays` | `30` | Сколько дней хранить историю сессий и контрольные точки |

Claude Code хранит снимки для **100 самых свежих контрольных точек**; более старые отбрасываются даже внутри окна хранения.

> **Обновление v2.1.117**: `cleanupPeriodDays` теперь задаёт срок хранения для многих кэшей на диске, а не только для контрольных точек (ниже — выборка; стенограммы сессий, `file-history/`, `plans/`, `debug/`, `paste-cache/` и другое тоже покрыты):
>
> - Контрольные точки сессий
> - `~/.claude/tasks/` — постоянные списки задач
> - `~/.claude/shell-snapshots/` — снятые снимки окружения оболочки
> - `~/.claude/backups/` — прежние версии `~/.claude.json` (пять новейших сохраняются)
>
> Одна настройка теперь одинаково подчищает эти каталоги через одно и то же число дней.

## Ограничения

У контрольных точек такие ограничения:

- **Изменения команд Bash НЕ отслеживаются** — операции вроде `rm`, `mv`, `cp` над файловой системой в контрольные точки не попадают
- **Внешние изменения НЕ отслеживаются** — правки вне Claude Code (в редакторе, терминале и т. д.) не сохраняются
- **Это не замена системе контроля версий** — для постоянных проверяемых изменений кодовой базы используйте git
- **Правки субагента НЕ восстанавливаются** — файлы, которые правил субагент, не отслеживаются, поэтому `/rewind` оставляет их как есть; исключение — навык `context: fork` на переднем плане, его правки восстанавливаются как у основной сессии

> **Обновление v2.1.216**: `/rewind` больше не восстанавливает и не удаляет файлы через символические или жёсткие ссылки по отслеживаемым путям. Если отслеживаемый путь проходит через символическую или жёсткую ссылку, перемотка пропускает его и не идёт по ссылке, а затем сообщает, сколько путей пропущено по этой причине.

## Устранение неполадок

### Пропавшие контрольные точки

**Проблема**: ожидаемая контрольная точка не найдена

**Решение**:
- Проверьте, не были ли контрольные точки очищены
- Проверьте место на диске
- Убедитесь, что `cleanupPeriodDays` задан достаточно большим (по умолчанию: 30 дней)

### Перемотка не удалась

**Проблема**: не удаётся перемотать к контрольной точке

**Решение**:
- Убедитесь, что незакоммиченные изменения не конфликтуют
- Проверьте, не повреждена ли контрольная точка
- Попробуйте перемотать к другой контрольной точке

## Интеграция с Git

Контрольные точки дополняют git (и не заменяют его):

| Свойство | Git | Контрольные точки |
|----------|-----|-------------------|
| Область | Файловая система | Разговор + файлы |
| Сохранность | Постоянно | В рамках сессии |
| Детализация | Коммиты | Любая точка |
| Скорость | Медленнее | Мгновенно |
| Общий доступ | Да | Ограниченно |

Используйте оба вместе:
1. Контрольные точки — для быстрых экспериментов
2. Git-коммиты — для законченных изменений
3. Создайте контрольную точку перед операциями git
4. Коммитьте удачные состояния контрольных точек в git

## Краткое руководство

### Базовый рабочий процесс

1. **Работайте как обычно** — Claude Code создаёт контрольные точки автоматически
2. **Хотите вернуться?** — нажмите `Esc` дважды или выполните `/rewind`
3. **Выберите контрольную точку** — выберите из списка, чтобы перемотать
4. **Выберите, что восстановить** — восстановить код и разговор, восстановить разговор, восстановить код, суммировать отсюда, суммировать досюда или отменить
5. **Продолжайте работу** — вы снова в той точке

### Сочетания клавиш

- **`Esc` + `Esc`** — открыть браузер контрольных точек
- **`/rewind`** — другой способ открыть контрольные точки
- **`/checkpoint`**, **`/undo`** — псевдонимы `/rewind`

## Когда пора перематывать: наблюдение за контекстом

Контрольные точки позволяют вернуться назад — но как понять, *когда* это стоит сделать? По мере роста разговора контекстное окно Claude заполняется, и качество модели тихо падает. Можно отгружать код от полуслепой модели и не замечать этого.

**[cc-context-stats](https://github.com/luongnv89/cc-context-stats)** решает это, добавляя в строку состояния Claude Code зоны контекста в реальном времени. Инструмент показывает, где вы находитесь в контекстном окне — от **Plan** (зелёная, можно планировать и писать код) через **Code** (жёлтая, не начинайте новые планы) к **Dump** (оранжевая, заканчивайте и перематывайте). Когда зона сменяется, пора поставить контрольную точку и начать заново, а не проталкивать работу с уже просевшим результатом.

## Итог

Контрольные точки — автоматическая функция Claude Code, которая позволяет безопасно исследовать разные подходы и не бояться потерять работу. Каждый промпт пользователя автоматически создаёт новую контрольную точку, поэтому перемотать можно к любой предыдущей точке сессии.

Главное:
- Смело экспериментируйте с несколькими подходами
- Быстро восстанавливайтесь после ошибок
- Сравнивайте разные решения рядом
- Безопасно сочетайте с системами контроля версий

Помните: контрольные точки не заменяют git. Контрольные точки — для быстрых экспериментов, git — для постоянных изменений кода.
