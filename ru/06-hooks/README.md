# Хуки

Хуки — это автоматические скрипты, которые выполняются в ответ на определённые события в сессиях Claude Code. Они дают автоматизацию, проверку, управление разрешениями и пользовательские рабочие процессы.

## Обзор

Хуки — это автоматические действия (команды оболочки, HTTP-вебхуки, промпты для LLM, вызовы инструментов MCP или оценки субагента), которые выполняются сами, когда в Claude Code происходит определённое событие. Они получают JSON на входе и сообщают результат кодом выхода и JSON на выходе.

**Ключевые возможности:**
- Автоматизация по событиям
- Вход и выход на основе JSON
- Типы хуков `command`, `http`, `mcp_tool`, `prompt` и `agent`
- Сопоставление по шаблону для хуков конкретного инструмента

## Конфигурация

Хуки задаются в файлах настроек в определённой структуре:

- `~/.claude/settings.json` — настройки пользователя (все проекты)
- `.claude/settings.json` — настройки проекта (можно делиться, попадают в коммит)
- `.claude/settings.local.json` — локальные настройки проекта (не коммитятся)
- Управляемая политика — настройки на всю организацию
- `hooks/hooks.json` плагина — хуки в области плагина
- Frontmatter навыка или агента — хуки на время жизни компонента

### Базовая структура конфигурации

```json
{
  "hooks": {
    "EventName": [
      {
        "matcher": "ToolPattern",
        "hooks": [
          {
            "type": "command",
            "command": "your-command-here",
            "timeout": 60
          }
        ]
      }
    ]
  }
}
```

**Ключевые поля:**

| Поле | Описание | Пример |
|-------|-------------|---------|
| `matcher` | Шаблон имён инструментов (с учётом регистра) | `"Write"`, `"Edit\|Write"`, `"*"` |
| `hooks` | Массив определений хуков | `[{ "type": "command", ... }]` |
| `type` | Тип хука: `"command"` (bash), `"prompt"` (LLM), `"http"` (вебхук), `"mcp_tool"` (вызов инструмента MCP, v2.1.118+) или `"agent"` (субагент) | `"command"` |
| `command` | Команда оболочки для выполнения | `"$CLAUDE_PROJECT_DIR/.claude/hooks/format.sh"` |
| `timeout` | Необязательный таймаут в секундах. По умолчанию: 600 для command/http/mcp_tool, 30 для prompt, 60 для agent. | `30` |
| `once` | Если `true`, хук удаляется после первого успешного запуска (неудачный, заблокированный или превысивший таймаут запуск его сохраняет). Только frontmatter навыка; в настройках и во frontmatter агента игнорируется | `true` |
| `async` | Если `true`, выполняется в фоне и не блокирует | `true` |
| `asyncRewake` | Если `true`, выполняется в фоне и будит Claude при коде выхода 2. Подразумевает `async`. | `true` |
| `shell` | Принимает `"bash"` или `"powershell"`. По умолчанию `"bash"`, а на Windows — `"powershell"`, если Git Bash не установлен. | `"bash"` |
| `statusMessage` | Пользовательское сообщение индикатора, пока хук выполняется | `"Форматирование…"` |
| `onFailure` | Что происходит с действием, когда командный или HTTP-хук не срабатывает (не может запуститься, истекает таймаут, выходит с неожиданным кодом): `"continue"` (по умолчанию) или `"block"` (v2.1.295+) | `"block"` |

> **Примечание**: у некоторых событий таймаут по умолчанию ниже. `UserPromptSubmit` снижает таймаут по умолчанию для `command`, `http` и `mcp_tool` до 30 секунд, а `MessageDisplay` — до 10 секунд. Хуки `SessionEnd` делят бюджет в 1,5 секунды; если в настройках у хука задан более длинный `timeout`, Claude Code поднимает этот бюджет до него, но не выше 60 секунд.

### Шаблоны matcher

| Шаблон | Описание | Пример |
|---------|-------------|---------|
| Точная строка | Совпадает с конкретным инструментом | `"Write"` |
| Регулярное выражение | Совпадает с несколькими инструментами | `"Edit\|Write"` |
| Через запятую | Совпадает с любым из перечисленных инструментов (v2.1.191+) | `"Write,Edit"` |
| Подстановка | Совпадает со всеми инструментами | `"*"` или `""` |
| Инструменты MCP | Шаблон сервера и инструмента | `"mcp__memory__.*"` |

> **Matcher сопоставляются точно (v2.1.195+).** Идентификатор с дефисом (например, имя инструмента MCP, в котором есть дефис) больше не совпадает случайно по подстроке с другим инструментом. Matcher через запятую вроде `"Write,Edit"` срабатывают на любой инструмент из списка — в более ранних сборках они молча не срабатывали никогда.

**Значения matcher для InstructionsLoaded:**

| Значение matcher | Описание |
|---------------|-------------|
| `session_start` | Инструкции загружены при старте сессии |
| `nested_traversal` | Инструкции загружены при вложенном обходе каталогов |
| `path_glob_match` | Инструкции загружены по совпадению glob-шаблона пути |

### Сужение условиями `if` (пути в аргументах инструмента)

Поле `matcher` выбирает хук по **имени инструмента** (`"Write"`, `"Edit|Write"`, `"*"`). Чтобы сузить фильтр по **аргументам** инструмента — например, запускать хук только когда правка затрагивает `src/`, или ограничить чтение файлов с секретами — добавьте условие `if` к отдельному обработчику хука. Это не то же самое, что matcher по имени инструмента: `matcher` решает, *какой инструмент*, а `if` — *какой вызов*.

`if` использует [синтаксис правил разрешений](https://code.claude.com/docs/en/permissions) (`ToolName(pattern)`) и оценивается по имени инструмента **и** его аргументам вместе. Для `Read`/`Edit`/`Write` шаблон пути следует семантике gitignore, с теми же якорями, что у правил разрешений: простое имя вроде `.env` совпадает на любой глубине, `src/**` считается от текущего каталога, `/src/**` — от корня проекта, `~/...` — от домашнего каталога, а `//...` — абсолютный путь в файловой системе.

Поле `if` стоит на **уровне обработчика хука** — рядом с `type` и `command`, внутри массива `hooks`, — а не на `matcher`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "if": "Edit(src/**)",
            "command": "./hooks/lint-src.sh"
          }
        ]
      },
      {
        "matcher": "Read",
        "hooks": [
          {
            "type": "command",
            "if": "Read(.env)",
            "command": "./hooks/block-secret-read.sh"
          }
        ]
      }
    ]
  }
}
```

Примеры допустимых шаблонов `if`: `Edit(src/**)` (правки внутри `src/`), `Read(~/.ssh/**)` (чтение любого SSH-ключа), `Read(.env)` (любой `.env` в текущем каталоге и ниже), `Bash(git push *)` (только подкоманды `git push`).

> **Обновление v2.1.214**: односегментный шаблон `dir/**` в условии `if` хука (как `Edit(src/**)`) теперь совпадает только с `<cwd>/dir` — не с этим каталогом на любой глубине дерева. Раньше `src/**` также совпадал с `foo/src/**`. Если нужно совпадение на любой глубине, используйте `**/dir/**`. **Важно**: это сужение действует только для условий `if:` хука и автоодобрения по правилам allow — правила разрешений deny/ask по-прежнему сопоставляют `dir/**` на любой глубине.

## Типы хуков

Claude Code поддерживает пять типов хуков:

### Командные хуки

Тип хука по умолчанию. Выполняет команду оболочки и общается через JSON на stdin/stdout и коды выхода.

```json
{
  "type": "command",
  "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/validate.py\"",
  "timeout": 60
}
```

#### Форма exec (`args`)

> Добавлено в v2.1.139.

Вместо формы оболочки `"command": "..."` командный хук может запустить бинарник напрямую через `execve()` с массивом `args`. Разбора оболочкой нет, поэтому заполнители путей не нужно брать в кавычки, а конфигурация не подвержена ошибкам внедрения в оболочку.

```json
{
  "type": "command",
  "command": "python3",
  "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/validate.py", "--strict"],
  "timeout": 60
}
```

`command` обязателен всегда: когда задан `args`, `command` — это исполняемый файл для запуска (ищется в `PATH`), а `args` — его вектор аргументов. Не указывайте `args` (форма оболочки), если нужны каналы, перенаправление, цепочки `&&` или подстановки оболочки; используйте `args`, когда вызываете один бинарник с аргументами.

### HTTP-хуки

> Добавлено в v2.1.63.

Удалённые конечные точки вебхука, которые получают тот же JSON, что и командные хуки. HTTP-хуки отправляют JSON методом POST на URL и получают JSON-ответ. Если песочница включена, HTTP-хуки идут через неё. Подстановка переменных окружения в значения заголовков из соображений безопасности требует явного списка `allowedEnvVars`.

```json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "http",
        "url": "https://my-webhook.example.com/hook"
      }]
    }]
  }
}
```

**Ключевые свойства:**
- `"type": "http"` — помечает это как HTTP-хук
- `"url"` — URL конечной точки вебхука
- Идёт через песочницу, когда песочница включена
- Для любой подстановки переменных окружения в значениях `headers` нужен явный список `allowedEnvVars`

### Промпт-хуки

Промпты, которые оценивает LLM: содержимое хука — это промпт, и его оценивает Claude. В основном используются с событиями `Stop` и `SubagentStop` для умной проверки, что задача завершена.

```json
{
  "type": "prompt",
  "prompt": "Оцените, выполнил ли Claude все запрошенные задачи.",
  "timeout": 30
}
```

LLM оценивает промпт и возвращает структурированное решение (подробности в разделе [Хуки на основе промптов](#хуки-на-основе-промптов)).

### Хуки инструментов MCP

> Добавлено в v2.1.118.

Тип `mcp_tool` напрямую вызывает настроенный инструмент MCP; в конфигурации указаны MCP-сервер и имя инструмента, а не команда оболочки или URL. Это удобно, когда логика проверки или реакции уже живёт в настроенном MCP-сервере.

```json
{
  "matcher": "Edit",
  "hooks": [{
    "type": "mcp_tool",
    "server": "my-mcp-server",
    "tool": "validate_edit",
    "input": { "file_path": "${tool_input.file_path}" }
  }]
}
```

**Ключевые свойства:**
- `"type": "mcp_tool"` — помечает это как хук инструмента MCP
- `"server"` — имя настроенного MCP-сервера
- `"tool"` — имя инструмента на этом сервере, который нужно вызвать
- `"input"` — необязательные аргументы инструмента; в строковых значениях работает подстановка `${path}` из JSON на входе хука, например `"${tool_input.file_path}"`

Аргументы инструмента берутся из `input` (с подстановкой `${path}`), а не напрямую из входа хука. Как настроить MCP-серверы, см. в [настройке MCP-сервера](../05-mcp/README.md).

### Хуки агента

Хуки проверки на субагенте: они запускают отдельного агента, чтобы оценить условия или выполнить сложные проверки. В отличие от промпт-хуков (оценка LLM за один ход), хуки агента могут пользоваться инструментами и рассуждать в несколько шагов.

> **Примечание**: хуки агента экспериментальные и могут измениться.

> **Примечание**: с v2.1.280 хуки агента не запускаются на `PermissionRequest` — их ответ всё равно не мог разрешить или отклонить запрос. Там используйте командный или HTTP-хук, который возвращает объект решения (`ok: false` у промпт-хука на `PermissionRequest` ни на что не влияет).

```json
{
  "type": "agent",
  "prompt": "Проверьте, что изменения кода следуют нашим архитектурным правилам. Сверьтесь с нужными документами по дизайну и сравните.",
  "timeout": 120
}
```

**Ключевые свойства:**
- `"type": "agent"` — помечает это как хук агента
- `"prompt"` — описание задачи для субагента
- Агент может пользоваться инструментами (Read, Grep, Bash и другими), чтобы выполнить оценку
- Возвращает структурированное решение, похожее на промпт-хуки

## События хуков

Claude Code поддерживает **33 события хуков**:

| Событие | Когда срабатывает | Вход matcher | Может блокировать | Типичное применение |
|-------|---------------|---------------|-----------|------------|
| **SessionStart** | Сессия начинается, возобновляется, очищается или контекст сжимается | startup/resume/clear/compact/fork | Нет | Настройка окружения |
| **Setup** | `--init-only` или `--init`/`--maintenance` с `-p` (подготовка CI и скриптов) | `init`/`maintenance` | Нет | Подготовка инструментов, установка зависимостей |
| **InstructionsLoaded** | После загрузки CLAUDE.md или файла правил | Причина загрузки (`session_start`/`nested_traversal`/`path_glob_match`/`include`/`compact`) | Нет | Журнал аудита и наблюдаемости |
| **UserPromptSubmit** | Пользователь отправляет промпт | (нет) | Да | Проверка промптов |
| **UserPromptExpansion** | Введённая слэш-команда или MCP-промпт раскрывается в промпт | Имя команды | Да | Преобразовать или проверить раскрытый промпт |
| **PreToolUse** | Перед выполнением инструмента | Имя инструмента | Да (allow/deny/ask/defer) | Проверка и изменение входных данных |

| **PostToolBatch** | После завершения пакета вызовов инструментов | (нет) | Да | Сводные отчёты, пакетная проверка |
| **Notification** | Отправлено уведомление | Тип уведомления | Нет | Пользовательские уведомления |
| **MessageDisplay** | Пока отображается текст сообщения ассистента | (нет) | Нет | Преобразовать или скрыть отображаемый текст сообщения (v2.1.152) |
| **SubagentStart** | Запущен субагент | Имя типа агента | Нет | Настройка субагента |
| **SubagentStop** | Субагент завершает работу | Имя типа агента | Да | Проверка субагента |
| **Stop** | Claude заканчивает ответ | (нет) | Да | Проверка завершения задачи |
| **StopFailure** | Ошибка API завершает ход | Тип ошибки (`rate_limit`, `overloaded`, `server_error`, …) | Нет | Восстановление после ошибки, журналирование |
| **TeammateIdle** | Напарник в команде агентов простаивает | (нет) | Да | Координация напарников |
| **TaskCompleted** | Задача отмечена выполненной | (нет) | Да | Действия после задачи |
| **TaskCreated** | Задача создана через TaskCreate | (нет) | Да | Учёт задач, журналирование |
| **ConfigChange** | Изменяется файл конфигурации | Источник конфигурации (`user_settings`/`project_settings`/`local_settings`/`policy_settings`/`skills`) | Да (кроме policy) | Реакция на обновления конфигурации |
| **CwdChanged** | Меняется рабочий каталог | (нет) | Нет | Настройка под конкретный каталог |

| **FileChanged** | Изменяется отслеживаемый файл | Имена файлов для наблюдения (например, `.envrc\|.env`) | Нет | Наблюдение за файлами, пересборка |

| **WorktreeCreate** | Создаётся worktree | (нет) | Да (возврат пути) | Инициализация worktree |
| **WorktreeRemove** | Worktree удаляется | (нет) | Да (ненулевой код выхода отменяет удаление) | Очистка worktree |
| **Elicitation** | MCP-сервер запрашивает ввод пользователя | Имя MCP-сервера | Да | Проверка ввода |
| **ElicitationResult** | Пользователь отвечает на elicitation | Имя MCP-сервера | Да | Обработка ответа |
| **SessionEnd** | Сессия завершается | Причина завершения (`clear`/`resume`/`logout`/`prompt_input_exit`/`other`) | Нет | Очистка, финальное журналирование |

`PreModelSwitch` и `PostModelSwitch` требуют v2.1.251 или новее. Оба получают `from_model` и `to_model`; matcher оценивается по каноническому имени, полученному из `to_model` (например, `claude-opus-5`, `.*opus.*`). Таймаут по умолчанию для их `command`, `http` и `mcp_tool` снижен до 30 секунд.

> **`TaskCreated` и `TaskCompleted` требуют включённых инструментов todo (v2.1.233).** Эти два
> события исходят от инструментов учёта задач и todo (`TaskCreate`/`Get`/`Update`/`List`,
> `TodoWrite`), которые **доступны по умолчанию только на моделях Claude 3.x, Opus с 4
> по 4.7, Sonnet с 4 по 4.6 и Haiku 4.5**. На других моделях хуки остаются корректной
> конфигурацией, но просто никогда не срабатывают — нет ни вывода, ни ошибки. Задайте
> `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`, чтобы вернуть инструменты, а вместе с ними и события.

> **Длительность PostToolUse (v2.1.119):** во вход хуков `PostToolUse` и `PostToolUseFailure` теперь входит `duration_ms` — подробности в разделе [PostToolUse](#posttooluse).

### PreToolUse

Запускается после того, как Claude создал параметры инструмента, и до обработки. Используйте это, чтобы проверить или изменить входные данные инструмента.

**Конфигурация:**
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/validate-bash.py"
          }
        ]
      }
    ]
  }
}
```

**Частые matcher:** `Agent`, `Bash`, `Glob`, `Grep`, `Read`, `Edit`, `Write`, `WebFetch`, `WebSearch`

**Управление выходом:**
- `permissionDecision`: `"allow"`, `"deny"`, `"ask"` или `"defer"`
  - `"allow"` пропускает запрос разрешения (кроме инструментов, которым нужно взаимодействие с пользователем, и инструментов коннектора, которые организация поставила в `ask`)
  - `"deny"` не даёт вызвать инструмент
  - `"ask"` просит подтвердить; в запросе указаны плагин или навык, откуда пришёл хук (v2.1.301)
  - `"defer"` завершается мягко, чтобы инструмент можно было продолжить позже; для этого значения `permissionDecisionReason`, `updatedInput` и `additionalContext` игнорируются
  - Правила deny и ask всё равно оцениваются независимо от того, что вернул хук. Когда несколько хуков `PreToolUse` расходятся, приоритет такой: `deny` > `defer` > `ask` > `allow`
- `permissionDecisionReason`: пояснение решения. Для `"ask"` показывается пользователю (не Claude); для `"deny"` показывается Claude; для `"allow"` и `"defer"` пишется только в журнал отладки
- `updatedInput`: замена входа инструмента (заменяет весь объект входа). С v2.1.300 проверяется так же, как собственный вход Claude — неизвестные ключи отбрасываются, а вход, который инструмент отвергает, отклоняет вызов

### PostToolUse

Запускается сразу после завершения инструмента. Используйте для проверки, журналирования или чтобы вернуть контекст Claude.

**Конфигурация:**
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/security-scan.py"
          }
        ]
      }
    ]
  }
}
```

**Управление выходом:**
- Решение `"block"` передаёт Claude обратную связь
- `additionalContext`: контекст, который добавляется для Claude

**Дополнительные поля входа (v2.1.119):**

| Поле | Тип | Описание |
|-------|------|-------------|
| `duration_ms` | number | Время выполнения инструмента в миллисекундах. Не включает время в запросах разрешения и в выполнении хука PreToolUse. Есть и у хуков `PostToolUse`, и у `PostToolUseFailure`. |

#### Восстанавливаемые блокировки (`continueOnBlock`, v2.1.139)

Командный хук, который возвращает `"decision": "block"` на `PostToolUse`, добавляет `reason` рядом с результатом инструмента; Claude по-прежнему видит исходный вывод. `continueOnBlock` — поле **промпт**-хука (у командных хуков и хуков агента его нет): по умолчанию промпт-хук, который возвращает `ok: false` на `PostToolUse`, заканчивает ход и показывает причину строкой предупреждения. Задайте на промпт-хуке `"continueOnBlock": true`, чтобы вместо этого вернуть причину Claude и продолжить ход: модель прочитает обратную связь и сможет повторить попытку или поправить работу.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Проверьте эту правку по нашей политике записи (например, пути только для чтения). Вход хука: $ARGUMENTS",
            "continueOnBlock": true
          }
        ]
      }
    ]
  }
}
```

Используйте это, когда `reason` хука — то, на что Claude может отреагировать (например, «этот файл только для чтения; пишите в другое место»); не включайте, если блокировка должна полностью остановить ход.

### UserPromptSubmit

Запускается, когда пользователь отправляет промпт, до того как Claude его обработает. С v2.1.299 он запускается до раскрытия навыка или пользовательской команды, поэтому блокировка промпта останавливает и строки оболочки `!` этой команды; `UserPromptExpansion` срабатывает после него.

**Конфигурация:**
```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/validate-prompt.py"
          }
        ]
      }
    ]
  }
}
```

**Управление выходом:**
- `decision`: `"block"`, чтобы не дать обработать промпт
- `reason`: пояснение, если заблокировано
- `additionalContext`: контекст, который добавляется к промпту

### Stop и SubagentStop

Запускаются, когда Claude заканчивает ответ (Stop) или субагент завершает работу (SubagentStop). Поддерживают оценку на основе промпта для умной проверки, что задача завершена.

**Дополнительное поле входа:** и хуки `Stop`, и хуки `SubagentStop` получают в JSON поле `last_assistant_message` с финальным сообщением Claude или субагента перед остановкой. Оно полезно, чтобы оценить, завершена ли задача.

**Конфигурация:**
```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Оцените, выполнил ли Claude все запрошенные задачи.",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

> **Предохранитель на подряд идущие блокировки (v2.1.143)**: если хук `Stop` возвращает `"decision": "block"` (или ставит `continue: false`) **8 раз подряд** для одного и того же хода, Claude Code отменяет следующую блокировку и заканчивает ход. Порог меняется переменной окружения `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP=<integer>` (поставьте `0`, чтобы отключить предохранитель полностью). Так сбойный хук Stop не зацикливает ход навсегда.

**Поле возврата (v2.1.163):** хук `Stop` или `SubagentStop` может вернуть `hookSpecificOutput.additionalContext`, чтобы дать Claude обратную связь и **продолжить ход, не показывая метку ошибки**. Раньше влиять на модель из хука Stop было неудобно; теперь хук может чисто подмешать контекст и обойти поведение старых путей обратной связи с меткой ошибки (таких как `"decision": "block"`).

```json
{
  "hookSpecificOutput": {
    "hookEventName": "Stop",
    "additionalContext": "Напоминание: запустите набор тестов, прежде чем объявлять работу законченной."
  }
}
```

**Конфигурация:**
```json
{
  "hooks": {
    "SubagentStart": [
      {
        "matcher": "code-review",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/subagent-init.sh"
          }
        ]
      }
    ]
  }
}
```

### SessionStart

Запускается, когда сессия стартует или возобновляется. Может сохранять переменные окружения.

**Matcher:** `startup`, `resume`, `clear`, `compact`, `fork`

> **Обновление v2.1.214**: форкнутая сессия теперь сообщает источник `"fork"` — раньше она сообщала `"resume"`.

**Особая возможность:** используйте `CLAUDE_ENV_FILE`, чтобы сохранить переменные окружения (это также доступно в хуках `CwdChanged` и `FileChanged`):

```bash
#!/bin/bash
if [ -n "$CLAUDE_ENV_FILE" ]; then
  echo 'export NODE_ENV=development' >> "$CLAUDE_ENV_FILE"
fi
exit 0
```

**Выходы в области сессии (v2.1.152):** хук `SessionStart` может вернуть JSON, чтобы заново просканировать навыки и задать заголовок сессии:

```json
{
  "reloadSkills": true,
  "hookSpecificOutput": {
    "sessionTitle": "Миграция платежей"
  }
}
```

`reloadSkills: true` на верхнем уровне запускает повторное сканирование навыков в той же сессии (то же действие, что у команды `/reload-skills`), и навыки, которые хук только что установил, сразу становятся доступны. `hookSpecificOutput.sessionTitle` задаёт отображаемый заголовок сессии при старте и возобновлении.

### SessionEnd

Запускается, когда сессия заканчивается, чтобы выполнить очистку или финальное журналирование. Не может заблокировать завершение.

**Значения поля reason:**
- `clear` — пользователь очистил сессию
- `resume` — сессия переключена через интерактивную `/resume`
- `logout` — пользователь вышел из системы
- `prompt_input_exit` — пользователь вышел через ввод промпта
- `other` — другая причина

**Конфигурация:**
```json
{
  "hooks": {
    "SessionEnd": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR/.claude/hooks/session-cleanup.sh\""
          }
        ]
      }
    ]
  }
}
```

### PreModelSwitch

Запускается **до** того, как Claude Code применит запрошенную смену модели — например, когда вы запускаете `/model` или когда компонент просит другую модель. Нужна v2.1.251 или новее.

**Matcher:** каноническое имя модели, на которую происходит переключение, полученное из `to_model`. Совпадайте с точной моделью (`claude-opus-5`) или с семейством по регулярному выражению (`.*opus.*`).

**Поля входа:** помимо общих полей хук получает `from_model` (модель, которая была до переключения) и `to_model` (запрошенная модель).

**Может блокировать:** да. Код выхода `2` блокирует переключение и показывает stderr как ошибку, поэтому сессия остаётся на текущей модели. Используйте это, чтобы разрешать или отклонять смену модели — например, чтобы не пускать чувствительный к стоимости проект на самую дорогую модель.

**Таймаут:** это событие снижает таймаут по умолчанию для `command`, `http` и `mcp_tool` до 30 секунд.

**Конфигурация:**
```json
{
  "hooks": {
    "PreModelSwitch": [
      {
        "matcher": ".*opus.*",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/gate-model-switch.sh"
          }
        ]
      }
    ]
  }
}
```

```bash
#!/bin/bash
# gate-model-switch.sh — отказ от переключения на Opus в этом проекте
input=$(cat)
to_model=$(echo "$input" | jq -r '.to_model')

if [[ "$to_model" == *opus* ]]; then
  echo "Для этого проекта заложен бюджет на Sonnet; остаёмся на текущей модели." >&2
  exit 2
fi

exit 0
```

### PostModelSwitch

Запускается **после** того, как модель сессии изменилась. Он срабатывает и на изменения, которые Claude Code делает сам — например, когда при возобновлении сессии восстанавливается ранее выбранная модель, — а не только на переключения, которые запрашиваете вы. Нужна v2.1.251 или новее.

**Matcher:** те же, что у `PreModelSwitch` — каноническое имя, полученное из `to_model`.

**Поля входа:** `from_model` и `to_model` рядом с общими полями.

**Может блокировать:** нет. Переключение уже произошло; хук может только наблюдать и реагировать.

**Таймаут:** это событие снижает таймаут по умолчанию для `command`, `http` и `mcp_tool` до 30 секунд.

**Конфигурация:**
```json
{
  "hooks": {
    "PostModelSwitch": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/log-model-switch.sh"
          }
        ]
      }
    ]
  }
}
```

```bash
#!/bin/bash
# log-model-switch.sh — дописывать каждое изменение модели в журнал сессии
input=$(cat)
from=$(echo "$input" | jq -r '.from_model')
to=$(echo "$input" | jq -r '.to_model')

echo "$(date -Iseconds) $from -> $to" >> ~/.claude/model-switches.log
exit 0
```

## Хуки в области компонента

Хуки можно прикрепить к конкретным компонентам (навыкам, агентам, командам) в их frontmatter:

**В SKILL.md, agent.md или command.md:**

```yaml
---
name: secure-operations
description: Выполнять операции с проверками безопасности
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/check.sh"
          once: true  # Только frontmatter навыка: удаляется после первого успешного запуска
---
```

**Поддерживаемые события:** все события хуков. Хуки субагента работают только пока субагент активен (`Stop` → `SubagentStop`); хуки навыка регистрируются, когда навык вызывают, и остаются активными до конца сессии.

Так хуки задаются прямо в компоненте, который ими пользуется, и связанный код остаётся вместе.

### Хуки во frontmatter субагента

Когда хук `Stop` задан во frontmatter субагента, он автоматически превращается в хук `SubagentStop`, ограниченный этим субагентом. Так хук остановки срабатывает только когда завершается этот конкретный субагент, а не когда останавливается основная сессия.

```yaml
---
name: code-review-agent
description: Субагент автоматического код-ревью
hooks:
  Stop:
    - hooks:
        - type: prompt
          prompt: "Проверьте, что код-ревью тщательное и полное."
  # Хук Stop выше автоматически превращается в SubagentStop для этого субагента
---
```

**Нужно доверие к рабочей области (v2.1.218):** хуки во frontmatter **проектного** субагента теперь требуют, чтобы доверие к рабочей области было принято для папки, из которой пришёл файл агента, прежде чем они запустятся. До v2.1.218 эти хуки могли запускаться из папок, которым вы не доверяли. Какие области исключены, см. в [документации по субагентам](https://code.claude.com/docs/en/sub-agents#hooks-in-subagent-frontmatter).

## Вход и выход хука

### JSON на входе (через stdin)

Все хуки получают JSON на вход через stdin:

```json
{
  "session_id": "abc123",
  "transcript_path": "/path/to/transcript.jsonl",
  "cwd": "/current/working/directory",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "/path/to/file.js",
    "content": "..."
  },
  "tool_use_id": "toolu_01ABC123...",
  "agent_id": "agent-abc123",
  "agent_type": "security-reviewer",
  "worktree": "/path/to/worktree",
  "effort": { "level": "medium" }
}
```

**Общие поля:**

| Поле | Описание |
|-------|-------------|
| `session_id` | Уникальный идентификатор сессии |
| `transcript_path` | Путь к файлу транскрипта разговора |
| `cwd` | Текущий рабочий каталог |
| `prompt_id` | UUID промпта, который обрабатывается; соотносится с атрибутом OpenTelemetry `prompt.id` (v2.1.196) |
| `hook_event_name` | Имя события, которое запустило хук |
| `agent_id` | Идентификатор агента, который выполняет этот хук |
| `agent_type` | Имя агента (например, `"Explore"` или `"security-reviewer"`); есть только когда сессия использует `--agent` или хук срабатывает внутри субагента |
| `worktree` | Путь к git worktree, если агент работает в нём |
| `effort.level` | (v2.1.133+) Активный уровень усилия: `low`, `medium`, `high`, `xhigh` или `max` |

### Коды выхода

| Код выхода | Значение | Поведение |
|-----------|---------|----------|
| **0** | Успех | Продолжить, разобрать JSON из stdout |
| **2** | Блокирующая ошибка | Заблокировать операцию, stderr показан как ошибка |
| **Другой** | Неблокирующая ошибка | Продолжить; заметка `<hook name> hook error` в транскрипте показывает первую строку stderr |

### JSON на выходе (stdout, код выхода 0)

```json
{
  "continue": true,
  "stopReason": "Необязательное сообщение, если останавливаемся",
  "suppressOutput": false,
  "systemMessage": "Необязательное предупреждение",
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "permissionDecisionReason": "Файл в разрешённом каталоге",
    "updatedInput": {
      "file_path": "/modified/path.js"
    }
  }
}
```

> **Область (v2.1.121+):** `hookSpecificOutput.updatedToolOutput` теперь учитывается для **всех** инструментов, не только для инструментов MCP. Хук `PostToolUse` на `Bash`, `Edit`, `Read` и других может переписать вывод инструмента до того, как его увидит Claude — удобно, чтобы скрыть секреты, нормализовать diff или отфильтровать шумный вывод команды. Значение должно совпадать с формой вывода инструмента — `Bash` возвращает объект с `stdout`, `stderr`, `interrupted` и `isImage`; для встроенных инструментов значение, которое не совпадает, игнорируется, и используется исходный вывод. Пример (убрать ANSI-коды цвета из вывода `Bash`):
>
> ```json
> {
>   "hookSpecificOutput": {
>     "hookEventName": "PostToolUse",
>     "updatedToolOutput": {
>       "stdout": "<вывод без ANSI-последовательностей>",
>       "stderr": "",
>       "interrupted": false,
>       "isImage": false
>     }
>   }
> }
> ```

> **`retry` (PermissionDenied)**: JSON `hookSpecificOutput.retry: true` говорит модели, что она может повторить отклонённый вызов инструмента.

> **Устаревшая форма решения `PreToolUse`**: для `PreToolUse` поля верхнего уровня `decision` и `reason` **устарели** — вместо них используйте `hookSpecificOutput.permissionDecision` (`allow` / `deny` / `ask` / `defer`) и `permissionDecisionReason`. Приоритет решений: `deny` > `defer` > `ask` > `allow`. Также `suppressOutput` принимается, но **ни на что не влияет**.

#### `terminalSequence` (v2.1.141)

Хуки могут выдавать сырые escape-последовательности OSC (команда операционной системы), задав `terminalSequence` в JSON на выходе. Хост пишет последовательность в свой управляющий терминал, когда хук возвращается — удобно для уведомлений рабочего стола, обновления заголовка окна и терминального звонка без собственного TTY.

| Поле | Тип | Описание |
|-------|------|-------------|
| `terminalSequence` | string | Сырая escape-последовательность (обычно OSC 9 / OSC 0 / OSC 777). Пишется в терминал хоста как есть. |

Пример — отправить уведомление рабочего стола OSC 9, когда длинная задача завершается. Запишите ESC и BEL как JSON-эскейпы (`\u001b`, `\u0007`) или соберите значение через `printf` и `jq`; сырые управляющие байты внутри JSON-строки не разбираются:

```json
{
  "terminalSequence": "\u001b]9;Задача выполнена\u0007"
}
```

Настройте это на хуке `Stop`, чтобы уведомление срабатывало, когда Claude заканчивает ход. Поддержка последовательностей зависит от терминала; iTerm2, Windows Terminal и WezTerm понимают OSC 9, а Kitty использует OSC 99.

import json
import sys
import re

BLOCKED_PATTERNS = [
    (r"\brm\s+-rf\s+/", "Блокировка опасной команды rm -rf /"),
    (r"\bsudo\s+rm", "Блокировка команды sudo rm"),
]

if __name__ == "__main__":

**Файл:** `.claude/hooks/security-scan.py`

```python
#!/usr/bin/env python3
import json
import sys
import re

SECRET_PATTERNS = [
    (r"password\s*=\s*['\"][^'\"]+['\"]", "Возможный захардкоженный пароль"),
    (r"api[_-]?key\s*=\s*['\"][^'\"]+['\"]", "Возможный захардкоженный API-ключ"),
]

def main():
    input_data = json.load(sys.stdin)

    tool_name = input_data.get("tool_name", "")
    if tool_name not in ["Write", "Edit"]:
        sys.exit(0)

    tool_input = input_data.get("tool_input", {})
    content = tool_input.get("content", "") or tool_input.get("new_string", "")
    file_path = tool_input.get("file_path", "")

    warnings = []
    for pattern, message in SECRET_PATTERNS:
        if re.search(pattern, content, re.IGNORECASE):
            warnings.append(message)

    if warnings:
        output = {
            "hookSpecificOutput": {
                "hookEventName": "PostToolUse",
                "additionalContext": f"Предупреждения безопасности для {file_path}: " + "; ".join(warnings)
            }
        }
        print(json.dumps(output))

    sys.exit(0)

if __name__ == "__main__":
    main()
```

### Пример 6: трекер использования контекста (пара хуков)

Считайте расход токенов на запрос, используя вместе хуки `UserPromptSubmit` (до сообщения) и `Stop` (после ответа).

**Файл:** `.claude/hooks/context-tracker.py`

```python
#!/usr/bin/env python3
"""
Трекер использования контекста — считает расход токенов на запрос.

UserPromptSubmit работает как хук «до сообщения», Stop — как хук «после ответа»:
по ним считается дельта расхода токенов для каждого запроса.

Способы подсчёта токенов:
1. Оценка по символам (по умолчанию): ~4 символа на токен, без зависимостей
2. tiktoken (необязательно): точнее (~90–95%), требуется: pip install tiktoken
"""
import json
import os
import sys
import tempfile

# Конфигурация
CONTEXT_LIMIT = 1000000  # 1M у Opus 5, Sonnet 5, Opus 4.8 и Sonnet 4.6; 200000 у Haiku 4.5 (подберите под свою модель)
USE_TIKTOKEN = False    # Поставьте True, если установлен tiktoken, — так точнее


def get_state_file(session_id: str) -> str:
    """Путь к временному файлу с числом токенов до сообщения, отдельно для каждой сессии."""
    return os.path.join(tempfile.gettempdir(), f"claude-context-{session_id}.json")


def count_tokens(text: str) -> int:
    """
    Считает токены в тексте.

    Если доступен tiktoken, берётся кодировка p50k_base (точность около 90–95%),
    иначе откат к оценке по символам (точность около 80–90%).
    """
    if USE_TIKTOKEN:
        try:
            import tiktoken
            enc = tiktoken.get_encoding("p50k_base")
            return len(enc.encode(text))
        except ImportError:
            pass  # Откат к оценке

    # Оценка по символам: ~4 символа на токен для английского текста
    return len(text) // 4


def read_transcript(transcript_path: str) -> str:
    """Читает файл транскрипта и склеивает всё содержимое."""
    if not transcript_path or not os.path.exists(transcript_path):
        return ""

    content = []
    with open(transcript_path, "r") as f:
        for line in f:
            try:
                entry = json.loads(line.strip())
                # Извлекаем текст из разных форматов сообщений
                if "message" in entry:
                    msg = entry["message"]
                    if isinstance(msg.get("content"), str):
                        content.append(msg["content"])
                    elif isinstance(msg.get("content"), list):
                        for block in msg["content"]:
                            if isinstance(block, dict) and block.get("type") == "text":
                                content.append(block.get("text", ""))
            except json.JSONDecodeError:
                continue

    return "\n".join(content)


def handle_user_prompt_submit(data: dict) -> None:
    """Хук до сообщения: сохранить текущее число токенов перед запросом."""
    session_id = data.get("session_id", "unknown")
    transcript_path = data.get("transcript_path", "")

    transcript_content = read_transcript(transcript_path)
    current_tokens = count_tokens(transcript_content)

    # Сохраняем во временный файл для последующего сравнения
    state_file = get_state_file(session_id)
    with open(state_file, "w") as f:
        json.dump({"pre_tokens": current_tokens}, f)


def handle_stop(data: dict) -> None:
    """Хук после ответа: посчитать и сообщить дельту токенов."""
    session_id = data.get("session_id", "unknown")
    transcript_path = data.get("transcript_path", "")

    transcript_content = read_transcript(transcript_path)
    current_tokens = count_tokens(transcript_content)

    # Загружаем число токенов до сообщения
    state_file = get_state_file(session_id)
    pre_tokens = 0
    if os.path.exists(state_file):
        try:
            with open(state_file, "r") as f:
                state = json.load(f)
                pre_tokens = state.get("pre_tokens", 0)
        except (json.JSONDecodeError, IOError):
            pass

    # Считаем дельту
    delta_tokens = current_tokens - pre_tokens
    remaining = CONTEXT_LIMIT - current_tokens
    percentage = (current_tokens / CONTEXT_LIMIT) * 100

    # Сообщаем расход
    method = "tiktoken" if USE_TIKTOKEN else "оценка"
    print(f"Контекст ({method}): ~{current_tokens:,} токенов (использовано {percentage:.1f}%, осталось ~{remaining:,})", file=sys.stderr)
    if delta_tokens > 0:
        print(f"Этот запрос: ~{delta_tokens:,} токенов", file=sys.stderr)


def main():
    data = json.load(sys.stdin)
    event = data.get("hook_event_name", "")

    if event == "UserPromptSubmit":
        handle_user_prompt_submit(data)
    elif event == "Stop":
        handle_stop(data)

    sys.exit(0)


if __name__ == "__main__":
    main()
```

**Конфигурация:**
```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/context-tracker.py\""
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/context-tracker.py\""
          }
        ]
      }
    ]
  }
}
```

**Как это работает:**
1. `UserPromptSubmit` срабатывает до обработки промпта — сохраняет текущее число токенов
2. `Stop` срабатывает после ответа Claude — считает дельту и сообщает расход
3. Каждая сессия изолирована через `session_id` в имени временного файла

**Способы подсчёта токенов:**

| Метод | Точность | Зависимости | Скорость |
|--------|----------|--------------|-------|
| Оценка по символам | ~80–90% | Нет | <1 мс |
| tiktoken (p50k_base) | ~90–95% | `pip install tiktoken` | <10 мс |

> **Примечание:** Anthropic не выпустил официальный офлайн-токенизатор. Оба способа — приближения. В транскрипт входят промпты пользователя, ответы Claude и выводы инструментов; с v2.1.300 туда же записываются системный промпт, инструменты и параметры каждого запроса к API.

### Пример 8: журнал прогресса обучения (SessionEnd)

Записывайте, какие модули вы изучали, в конце каждой сессии Claude Code. Прогресс хранится
в `~/.claude-howto-progress.json` — вне репозитория, поэтому он переживает `git pull` и
не затирается.

**Почему `SessionEnd`, а не `Stop`?**
`Stop` срабатывает после *каждого* ответа Claude. `SessionEnd` срабатывает один раз, когда сессия
завершается — ровно то, что нужно для записи в дневник в конце сессии.

**Почему нет интерактивного запроса?**
Хуки работают без управляющего терминала, поэтому `/dev/tty` недоступен и хук не может
спросить вас. Передайте модули (и необязательные заметки) переменными окружения, когда
запускаете Claude Code, например `CLAUDE_HOWTO_MODULES=06,07 claude`.

**Файл:** `06-hooks/session-end.sh`

```bash
#!/usr/bin/env bash
# Хук SessionEnd: записывает пройденные модули, затем дописывает запись сессии
# в ~/.claude-howto-progress.json для постоянного учёта прогресса обучения.

PROGRESS_FILE="$HOME/.claude-howto-progress.json"

# Защита: запускать только внутри этого репозитория
if [[ "$CLAUDE_PROJECT_DIR" != *"claude-howto"* ]] && [[ "$PWD" != *"claude-howto"* ]]; then
  exit 0
fi

if [ ! -f "$PROGRESS_FILE" ]; then
  echo '{"sessions":[]}' > "$PROGRESS_FILE"
fi

DATE=$(date +"%Y-%m-%d")
TIME=$(date +"%H:%M")

# Пройденные модули, например запуск: CLAUDE_HOWTO_MODULES=06,07 claude
# 01=Слэш  02=Память  03=Навыки  04=Субагенты  05=MCP
# 06=Хуки  07=Плагины 08=Контрольные точки 09=Продвинутое 10=CLI
INPUT="${CLAUDE_HOWTO_MODULES:-}"

if [ -z "$INPUT" ] || [ "$INPUT" = "skip" ]; then
  exit 0
fi

MODULES_JSON=$(echo "$INPUT" | tr ',' '\n' | tr -d ' ' | while read -r m; do
  case "$m" in
    01) echo '"01-slash-commands"' ;;
    02) echo '"02-memory"' ;;
    03) echo '"03-skills"' ;;
    04) echo '"04-subagents"' ;;
    05) echo '"05-mcp"' ;;
    06) echo '"06-hooks"' ;;
    07) echo '"07-plugins"' ;;
    08) echo '"08-checkpoints"' ;;
    09) echo '"09-advanced-features"' ;;
    10) echo '"10-cli"' ;;
    *)  echo "\"$m\"" ;;
  esac
done | paste -sd ',' -)

# Необязательные заметки, например CLAUDE_HOWTO_NOTES="попробовал пример pre-commit"
NOTES="${CLAUDE_HOWTO_NOTES:-}"

# Передаём NOTES отдельным аргументом, чтобы Python экранировал JSON —
# так JSON не ломается, если в заметках есть кавычки или обратные слэши.
python3 - "$PROGRESS_FILE" "$DATE" "$TIME" "$MODULES_JSON" "$NOTES" <<'PYEOF'
import sys, json

path, date, time_str, modules_raw, notes = sys.argv[1], sys.argv[2], sys.argv[3], sys.argv[4], sys.argv[5]

new_session = {
    "date": date,
    "time": time_str,
    "modules": json.loads(f"[{modules_raw}]") if modules_raw else [],
    "notes": notes,
}

with open(path, 'r') as f:
    data = json.load(f)

data.setdefault('sessions', []).append(new_session)

with open(path, 'w') as f:
    json.dump(data, f, indent=2)
PYEOF

echo " Сохранено в $PROGRESS_FILE"
```

```

    {
      "date": "2026-04-18",
      "time": "14:32",
      "modules": ["06-hooks", "07-plugins"],
      "notes": "Установил первый хук, попробовал пример pre-commit"
    }

```

**Показанные ключевые приёмы:**

| Приём | Почему это важно |
|---------|----------------|
| Событие `SessionEnd` | Срабатывает один раз при выходе — не после каждого ответа, как `Stop` |
| `INPUT="${CLAUDE_HOWTO_MODULES:-}"` | У хуков нет терминала (`/dev/tty` недоступен), поэтому ввод приходит из переменных окружения |
| `"timeout": 10` | Хуки SessionEnd отменяются через 1,5 с, если не задали свой `timeout` |
| `$CLAUDE_PROJECT_DIR` | Переносимый путь — не прописывайте жёстко `/Users/yourname/...` |
| Защитная проверка в начале | Не даёт хуку работать в посторонних проектах, если он установлен глобально |
| Хранить вне репозитория | Путь `~/` переживает `git pull`, и ваши данные не затираются |

## Хуки плагинов

Плагины могут включать хуки в файл `hooks/hooks.json`:

**Файл:** `plugins/hooks/hooks.json`

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/validate.sh"
          }
        ]
      }
    ]
  }
}
```

**Переменные окружения в хуках плагина:**
- `${CLAUDE_PLUGIN_ROOT}` — путь к каталогу плагина
- `${CLAUDE_PLUGIN_DATA}` — путь к каталогу данных плагина

Так плагины могут включать собственные хуки проверки и автоматизации.

## Хуки инструментов MCP

Инструменты MCP следуют шаблону `mcp__<server>__<tool>`:

```json
{
  "hooks": {

      {

            "command": "echo '{\"systemMessage\": \"Операция с памятью записана в журнал\"}'"

    ]
  }
}
```

## Соображения безопасности

### Отказ от ответственности

**ИСПОЛЬЗУЙТЕ НА СВОЙ СТРАХ И РИСК**: хуки выполняют произвольные команды оболочки. Только вы отвечаете за:
- Команды, которые настраиваете
- Разрешения на доступ к файлам и их изменение
- Возможную потерю данных или повреждение системы
- Проверку хуков в безопасном окружении до использования в продакшене

### Заметки по безопасности

- **Нужно доверие к рабочей области:** команды вывода хуков `statusLine` и `fileSuggestion` теперь требуют, чтобы доверие к рабочей области было принято, прежде чем они начнут действовать.
- **Размер терминала для строки статуса (v2.1.153):** скрипты команды строки статуса теперь получают переменные окружения `COLUMNS` и `LINES`, поэтому скрипт может подстроить вывод под ширину и высоту терминала (например, `[ "$COLUMNS" -lt 80 ] && short_output`).
- **HTTP-хуки и переменные окружения:** HTTP-хукам нужен явный список `allowedEnvVars`, чтобы подставлять переменные окружения в значения заголовков. Так чувствительные переменные окружения случайно не утекут на удалённые конечные точки.
- **Иерархия управляемых настроек:** настройка `disableAllHooks` теперь учитывает иерархию управляемых настроек: настройки уровня организации могут принудительно отключить хуки, и отдельный пользователь это не переопределит.
- **Автоодобрение PowerShell (v2.1.119):** команды инструмента PowerShell можно автоодобрять в режиме разрешений, как и Bash. Для пользователей Windows, которые запускают Claude Code с инструментами оболочки на PowerShell, это выравнивает поведение.
- **Закрыто автоодобрение Bash с голым присваиванием переменной (v2.1.145):** до v2.1.145 команда Bash вида `FOO=bar somecommand` (голое присваивание переменной в одной строке с командой не из списка разрешений) могла быть автоодобрена, если в списке разрешений было только само `FOO=bar`. v2.1.145 это закрывает — такие команды теперь попадают в запрос разрешения. Скрипты, которые полагались на неявное разрешение, начнут спрашивать; разрешите их явно правилом разрешения `Bash(...)`, которое покрывает всю команду, а не только присваивание переменной.

### Рекомендации

| Делайте | Не делайте |
|-----|-------|
| Проверяйте и очищайте все входные данные | Слепо доверять входным данным |
| Берите переменные оболочки в кавычки: `"$VAR"` | Использовать без кавычек: `$VAR` |
| Блокируйте обход пути (`..`) | Разрешать произвольные пути |
| Используйте абсолютные пути с `$CLAUDE_PROJECT_DIR` | Жёстко прописывать пути |
| Пропускайте чувствительные файлы (`.env`, `.git/`, ключи) | Обрабатывать все файлы |
| Сначала проверяйте хуки отдельно | Выкатывать непроверенные хуки |
| Для HTTP-хуков явно задавайте `allowedEnvVars` | Открывать вебхукам все переменные окружения |

## Подробности выполнения хуков

| Аспект | Поведение |
|--------|----------|
| **Таймаут** | По умолчанию 600 секунд для command/http/mcp_tool (30 для prompt, 60 для agent); настраивается для каждого хука |
| **Параллельность** | Все подходящие хуки выполняются параллельно; с v2.1.302 одновременно выполняется не больше 12 промпт-хуков или хуков agent одного события, остальные ждут своей очереди. |
| **Дедупликация** | Одинаковые команды хуков дедуплицируются |
| **Окружение** | Запуск в текущем каталоге с окружением Claude Code |

## Устранение неполадок

### Хук не выполняется
- Проверьте, что синтаксис JSON-конфигурации верный
- Проверьте, что шаблон matcher совпадает с именем инструмента
- Убедитесь, что скрипт существует и исполняемый: `chmod +x script.sh`
- Запустите `claude --debug`, чтобы увидеть журналы выполнения хуков
- Проверьте, что хук читает JSON из stdin (не из аргументов команды)

### Хук блокирует неожиданно
- Проверьте хук на примере JSON: `echo '{"tool_name": "Write", ...}' | ./hook.py`
- Проверьте код выхода: для разрешения должен быть 0, для блокировки — 2
- Проверьте вывод stderr (он показывается при коде выхода 2)

### Ошибки разбора JSON
- Всегда читайте из stdin, не из аргументов команды
- Разбирайте JSON по-настоящему (не манипулируйте строками)
- Обрабатывайте отсутствующие поля мягко
